# A6 – Security Misconfiguration

## Scenario

- Session secret hard-code trong source code
- Express lộ thông tin `X-Powered-By: Express`
- Sequelize logging SQL query ra console
- `NODE_ENV` không set = chạy ở chế độ development

## Mô tả lỗ hổng

Cấu hình mặc định hoặc không an toàn làm lộ thông tin hệ thống, giúp attacker dễ tấn công hơn.

## Khai thác

### Hard-coded session secret

**Vị trí code (v1):** `server.js`

```js
secret: 'keyboard cat'  // ai cũng biết default secret này
```

Attacker biết secret → forge session cookie.

### X-Powered-By header

Response header: `X-Powered-By: Express`

Lộ thông tin framework → attacker biết để target lỗ hổng Express cụ thể.

### SQL logging

```js
// sequelize tự log toàn bộ query ra stdout
// production log không nên có query chi tiết
```

## Tác động (Impact)

- Forge session với secret biết trước → chiếm bất kỳ session
- Fingerprinting framework → tấn công có chủ đích hơn
- Log SQL query lộ thông tin DB schema

## Fix (v2)

### Session secret từ environment:
```js
secret: process.env.SESSION_SECRET || 'fallback-dev-only'
```

### Tắt X-Powered-By:
```js
app.disable('x-powered-by')
```

### Tắt Sequelize logging khi production:
```js
new Sequelize(..., {
  logging: process.env.NODE_ENV !== 'production' ? console.log : false
})
```

### Set NODE_ENV trong vars.env / docker-compose:
```
NODE_ENV=production
SESSION_SECRET=<random-long-string>
```

## Kết quả sau fix

- Session không thể bị forge từ secret đã biết
- Header `X-Powered-By` không còn trong response
- SQL query không log ra production console
