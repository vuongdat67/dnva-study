# A1 – Injection

## Scenario

- SQL Injection: `/usersearch`, `/products`
- Command Injection: `/ping`

## Mô tả lỗ hổng

Injection xảy ra khi dữ liệu không tin cậy (user input) được đưa trực tiếp vào trình thông dịch (SQL, OS shell) mà không qua validation hoặc escaping.

## Khai thác

### SQL Injection – `/usersearch`

**Vị trí code (v1):** `core/appHandler.js` – hàm `userSearch`

```js
var query = "SELECT name,id FROM Users WHERE login='" + req.body.login + "'";
db.sequelize.query(query, { model: db.User })
```

**Payload:**
```
' OR 1=1 --
```

**Kết quả:** Trả về toàn bộ danh sách user trong DB.

**Ảnh minh chứng:** `report/3.1.2_A01_usersearch.png`, `report/3.1.3_A01_usersearch_test_id.png`

---

### Command Injection – `/ping`

**Vị trí code (v1):** `core/appHandler.js` – hàm `ping`

```js
exec('ping -c 3 ' + req.body.address, ...)
```

**Payload:**
```
127.0.0.1; cat /etc/passwd
```

**Kết quả:** Thực thi lệnh tùy ý trên server.

**Ảnh minh chứng:** `report/3.1.4_A01_ping.png`

## Tác động (Impact)

- Đọc / xóa / sửa toàn bộ dữ liệu trong DB
- Thực thi lệnh hệ thống, chiếm quyền server

## Fix (v2)

### SQLi fix:
```js
db.User.findOne({ where: { login: req.body.login } })
```
Dùng Sequelize ORM với parameterized query, không ghép chuỗi trực tiếp.

### Command Injection fix:
```js
const execFile = require('child_process').execFile;
execFile('ping', ['-c', '3', req.body.address], ...)
```
Dùng `execFile` truyền từng argument riêng → không thể inject shell operator.

## Kết quả sau fix

- Payload SQLi trả về "User not found" thay vì dump DB.
- Payload command injection không thực thi được lệnh thêm.
