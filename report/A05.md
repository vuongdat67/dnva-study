# A5 – Broken Access Control

## Scenario

- IDOR tại `/useredit` — user thường sửa thông tin người khác
- Admin endpoint `/admin/usersapi` — không kiểm tra role

## Mô tả lỗ hổng

Không có kiểm tra quyền sở hữu (ownership) khi cập nhật thông tin user. Bất kỳ user đã đăng nhập nào cũng có thể sửa thông tin của user khác bằng cách thay đổi `id` trong request.

## Khai thác

### IDOR – `/useredit`

**Vị trí code (v1):** `core/appHandler.js` – hàm `userEditSubmit`

```js
db.User.update(data, { where: { id: req.body.id } })
```

Không kiểm tra `req.body.id` có phải `req.user.id` không.

**Bước tấn công:**
1. Đăng nhập với tài khoản user thường (id=2)
2. Gửi POST `/useredit` với body: `id=1&name=Hacked&email=hacked@evil.com`
3. Thông tin của admin (id=1) bị thay đổi

### Admin API không kiểm tra role

```js
router.get('/admin/usersapi', authHandler.isAuthenticated, appHandler.listUsersAPI)
```

Middleware chỉ check `isAuthenticated`, không check `role === 'admin'`.

## Tác động (Impact)

- Chiếm tài khoản admin bằng cách đổi email/password
- Đọc dữ liệu nhạy cảm của mọi người dùng

## Fix (v2)

### IDOR fix:
```js
db.User.update(data, { where: { id: req.user.id } })
// Chỉ cập nhật đúng user đang đăng nhập
```

### Admin route fix:
```js
function requireAdmin(req, res, next) {
  if (req.user && req.user.role === 'admin') return next()
  res.status(403).json({ error: 'Forbidden' })
}
router.get('/admin/usersapi', authHandler.isAuthenticated, requireAdmin, appHandler.listUsersAPI)
```

## Kết quả sau fix

- User thường không thể sửa thông tin người khác
- `/admin/usersapi` trả 403 cho tài khoản không phải admin
