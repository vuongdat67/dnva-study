# A2 – Broken Authentication

## Scenario

- Chức năng quên mật khẩu: `/forgotpw`, `/resetpw`

## Mô tả lỗ hổng

Token reset password được tạo từ `md5(login)` — hàm băm không ngẫu nhiên, có thể tái tạo nếu biết tên đăng nhập. Không có thời gian hết hạn token.

## Khai thác

**Vị trí code (v1):** `core/authHandler.js`

```js
var token = md5(req.body.login)
// link: /resetpw?token=<md5>&login=<username>
```

**Bước tấn công:**
1. Biết login của nạn nhân (vd: `admin`)
2. Tự tính: `md5('admin')` = `21232f297a57a5a743894a0e4a801fc3`
3. Truy cập: `/resetpw?token=21232f297a57a5a743894a0e4a801fc3&login=admin`
4. Đặt lại mật khẩu tùy ý → chiếm tài khoản

## Tác động (Impact)

- Chiếm tài khoản bất kỳ người dùng nào khi biết username
- Không cần biết mật khẩu hiện tại

## Fix (v2)

```js
const crypto = require('crypto')
const token = crypto.randomBytes(32).toString('hex')
const tokenHash = crypto.createHash('sha256').update(token).digest('hex')
// Lưu tokenHash + expiry vào bảng PassReset (15 phút)
// Gửi token gốc qua email
```

- Token 32 bytes ngẫu nhiên, không đoán được
- Hash SHA256 lưu trong DB, token gốc chỉ gửi qua email
- Token hết hạn sau 15 phút

## Kết quả sau fix

- Không thể tính trước token
- Token hết hạn ngăn tấn công replay
